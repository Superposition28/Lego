Documentation Guide & Format Analysis Conventions

Project: Traveller's Tales (TT Games) Shared Architecture Reversing & Format Documentation

1. Project Mission & Two-Tier Hierarchy

This repository documents binary file formats, proprietary archive packaging, compression algorithms, 3D geometry pipelines, and filesystem structures across Traveller's Tales (TT Games / TT Fusion) LEGO titles within the RemakeEngine ecosystem. Documentation is divided into two complementary tiers with strict scoping rules:

  • Global Parent LEGO Documentation (EngineApps/Games/Lego/reversing/docs/Travellers_Tales/ — this suite): Acts as the unified, cross-generation master specification. It combines all format versions across engine eras (Nu2, NXG, DX11, NTT, and Double Eleven remasters), maps platform differences (PS2, Original Xbox, GameCube, PS3, Xbox 360, PC), records multi-title file censuses, and documents how a multi-era parser detects and dispatches every known variant.
  • Individual Game Documentation (EngineApps/Games/Lego/Games/<Game>/reversing/docs/): Scoped strictly to the specific format versions, container variants, and directory layouts present in that game. Individual game format pages must include minimal or no coverage of past or future variants from other titles — instead linking or referring back to this parent LEGO documentation for cross-era history — while still being completely self-contained so an implementer can build a working parser for that game's files alone.

2. Two Complementary Trees Within Each Documentation Suite

  1. Format Analysis (Formats/): Follows binary format origins: root executable and container formats (.xex/.xbe, .bin/ELF, .exe, .dat/.hdr/.datwin) followed by formats extracted from within archives (datFormats/).
  2. Game Files & Asset Use (Files/): Documents directory hierarchies, format censuses, sound banks, character definitions, mission scripts, and in-game usage through a combined virtual filesystem.

3. Expected Level of Detail (Standalone Clean-Room Specification Standard)

Whenever a format is understood (in either the parent shared documentation or an individual game module), its specification page must serve as a complete, self-contained engineering reference. An independent developer must be able to read the documentation alone and implement a working parser or converter without inspecting or depending on RemakeEngine's own parser implementations.

Every fully understood format page must include:

  • Scope, Magic Signatures & Endianness Rules: Exact 4CC/magic bytes, version ranges, and byte-order conventions (including mixed-endian structures such as big-endian HSEM chunk tables paired with little-endian PC float32 vertex coordinates).
  • Complete Binary Layout Tables: Byte-offset tables (Offset, Size, Type, Field, Description) covering container headers, nested chunks, descriptor arrays, vertex/index streams, and trailing structures.
  • Attribute Encodings & Mathematical Formulas: Exact type tables, bitmask meanings, half-float / unsigned-byte normalization equations (e.g., UByteN4 via (b / 127.5) - 1.0), coordinate transforms (e.g., WorldBind[b] = m2[b]^-1), and triangle topology/winding rules (triangle list vs. alternating-parity strip, CCW vs. CW front-face conversion).
  • Filtering, Back-References & Edge Cases: Explicit handling of shared buffer IDs (e.g., 0xC000xxxx), pass flags (e.g., unk1 != 0 shadow/depth prepasses), LOD selection (LOGH / NuLayer), and empty locator files.
  • End-to-End Pseudocode: Clear, self-contained pseudocode showing the complete parsing and reconstruction flow from raw file bytes to decoded output.
